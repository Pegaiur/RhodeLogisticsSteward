# 基建排班策略概要

> **版本**: 2026-05-26 · MVP — 全box满练，单次12h排班，产能最大化

## 核心原则

**MVP 阶段唯一目标：全box满练（415干员，全精2），243布局，单次12小时排班下的产能最大化。**

不做多班次轮换，不做 box 大小适配，不做练度过滤——这些都属于 MVP 之后的扩展。当前只需要回答一个问题：**在 29 个核心工位上，放哪 29 个人能让 12 小时产出最高？**

## 数据链路

| 文件 | 来源 | 内容 |
|------|------|------|
| `character_identity.json` | ArknightsGameData 清洗 | 415 干员 → buffId + phase；交叉核验 520 条基建 buff |
| `buffs_infrastructure.json` | ArknightsGameData 清洗 | buffId → roomType + efficiency + description（含联动条件文本） |
| `operators_data.json` | MAA OperBox 回调 | 玩家干员练度（MVP 阶段全部视为精2满级，仅校验干员持有） |

## 设施容量（243 布局）

| 设施 | 房间数 | 每间 | 总工位 |
|------|--------|------|--------|
| Control | ×1 | 5 | 5 |
| Trade | ×2 | 3 | 6 |
| Mfg | ×4 | 3 | 12 |
| Power | ×3 | 1 | 3 |
| Reception | ×1 | 2 | 2 |
| Office | ×1 | 1 | 1 |

> 核心工位 29 个。全box 415 干员中精2可用 ≥225 名 → 干员/工位比 ≈ 7.8:1。约束复杂度不在"有没有人"，而在"选谁最好"——典型的**组合优化**问题。

## 约束

**硬约束（不可违反）：**

| # | 约束 | 说明 |
|---|------|------|
| H1 | 人数上限 | Control≤5, Trade≤3/间, Mfg≤3/间, Power≤1/间, Reception≤2, Office≤1 |
| H2 | 一干员一工位 | 同一干员不能同时出现在两个房间 |
| H3 | 技能解锁 | MVP 全部精2 → 所有技能可用，此约束自然满足 |
| H4 | 设施类型匹配 | 干员技能 `roomType` 必须匹配目标设施 |
| H5 | 产物类型匹配 | 制造站产物必须匹配干员技能（如赤金房只取赤金相关技能） |

**软约束（优化目标）：**

唯一优化目标 = **12 小时总产出最大化**。产出 = `base_rate × ∫₀¹² P(t) dt`，其中 `P(t)` 是房间总生产力函数（见下节）。

单班次无轮换 → 心情平衡（S2）、宿舍恢复（S3）不适用。心情对产出的影响由 `e(t)` 模型的注意力涣散截断自然处理，不需要额外的软约束项。

## 策略

### 求解思路

制造站贡献 12h 产出的 ~60-70%（经验直接用、赤金喂贸易站），且候选池受产物约束（作战记录 60 人、赤金 56 人），远小于贸易站（74 人无产物约束）。因此**从制造站入手精确求解**，剩余设施贪心——在精度和计算量之间取得平衡。

制造站 60 人选 3 人，单产物全组合 C(60,3)=34,220 种。数量上可行，但 96% 的组合因联动缺失、效率不足而不可能成为最优。四条剪枝规则将实际评估压缩到 ~3,000 种。

### 求解器架构

```
全box干员池 (415人, 全精2)
       │
       ▼
Phase 1: 预计算（常数层，无需知道谁入选）
   B2 工程机器人 = f(layout)
   B4 魔物料理 = f(宿舍配置)
   中枢全局效率 = f(固定方案: 令+重岳+夕+凯尔希+焰尾)
   估计 BuffPool（B1 人间烟火/感知信息）
       │
       ▼
Phase 2: 制造站穷举（含完整 A1-A6 联动评估）
   按产物分离 (CR 60人 / PG 56人)
   剪枝规则过滤 → ~3,000 种组合
   每种组合: 计算个体效率 + A1-A6 同房联动 → 产出积分
   排序，保留全部组合（仅 ~3,000 种，无需截断）
       │
       ▼
Phase 3: 制造站跨间贪心分配
   for each product_type (CR x2间, PG x2间):
       组合按产出降序
       for combo in sorted_list:
           if 无干员冲突: 选中
           凑满 2 间后跳出
       │
       ▼
Phase 4: 剩余设施贪心
   Trade(6人) → Control(5人, 固定方案) → Power(3人) → Reception(2人) → Office(1人)
   从剩余池按支配偏序贪心取值
       │
       ▼
Phase 5: 精确验证
   用完整 B 层参数重新积分全方案
   逐房间计算 P(t) = 1 + 0.01n + (Σ per_op + synergy) / 100
   输出 = base_rate × ∫₀¹² P(t) dt
```

无回溯环节。Phase 2 的组合级排序已吸收联动评估——冲突时排在前面的组合就是更优的，等价干员换人零损失。

### 效率模型：e(t) 统一归约

所有技能效率统一归约为时间函数 `e(t)`，表示为 `LinearSegment` 列表。四种基本形态覆盖全部 520 条基建 buff：

| 形态 | e(t) 表达式 | 数量 | 示例 |
|------|------------|:---:|------|
| 常数 | `k` | ~555 | `manu_prod_spd[000]` efficiency=15 |
| 线性爬升 | `min(k₀ + r·t, ceiling)` | 7 | "首小时+15%, 此后+1%/h, 上限+20%" |
| 心情门控 | `k₁` 或 `k₂`（mood 阈值切换） | ~15 | mood<12→人间烟火+15, mood>12→感知信息+10 |
| 体系联动 | 跨干员聚合后输出常数段 | ~150 | "与推进之王同贸易站时+35%" |

心情耗尽（`mood=0`）时触发注意力涣散，所有技能 `e(t)=0`。单次 12h 班次中，最差单人工位 `burn=1.5/h` → `t_red = 16h` → 12h 内不触发截断，`e(t)` 全程为常数段。

详细建模见 [`efficiency-function-design.md`](./efficiency-function-design.md)。

### 房间生产力

房间总生产力为 `P(t) = 1 + 0.01·n + Σ eᵢ(t)/100`，其中 `n` 为房间人数，`eᵢ(t)` 含干员独立技能 + 体系联动产出。

12 小时总产出 = `base_rate × ∫₀¹² P(t) dt`。

### 制造站穷举与剪枝

制造站干员池按角色分层：

| 层级 | 人数 | 示例 | 作用 |
|------|:---:|------|------|
| 纯效率（无联动角色） | 36 | 白雪、薄绿、玛露西尔、铅踝 | 纯输出，彼此等价 |
| A-tier (eff≥30) | 23 | 地灵(35)、裂响(35)、食铁兽(35) | 高个体效率 |
| 联动锚点 | 11 | 水月、多萝西、海沫、森蚺、温蒂 | 触发 A1-A5 同房联动 |
| 技能提供者 | 25 | 白面鸮(莱茵)、杰西卡(标准化)、野鬃(红松) | 为锚点提供计数池 |

四条剪枝规则将 C(60,3)=34,220 种压缩至 ~1,500 种实际联动评估：

**规则 1：纯效率等价类合并。** 36 个纯效率干员之间无任何联动关系，所有 C(36,3)=7,140 种组合产出完全等价。保留一种代表，其余不生成。

**规则 2：联动锚点 × 配套池筛选。** "有水月没标准化提供者"是死组合——联动锚点必须有配套才有价值。候选池仅保留：联动锚点(11) + 锚点强制配套 + A-tier Top-K 冗余备选，压缩至 ~5,500 种。

**规则 3：逐槽位上界预判（运行时剪枝）。** 先算纯效率最优组合得 `best_known`。每个候选组合：

```
upper_bound = Σ个体效率 + max_theoretical_synergy(组合可触发的联动上限)
if upper_bound < best_known × 0.95: 跳过
```

O(1) 判定，无需计算联动。预计过滤 60-80%，余 ~1,500 种进入完整评估。

**规则 4：产物分离。** 作战记录和赤金两条独立链，各自只评估匹配产物的技能。两套独立跑，不互相污染。

> 每个产物类型 ~1,500 种 × 两次 = ~3,000 次完整房间评估。每次评估含 A1-A6 联动计算（查表 + 简单算术），Python < 5ms/次 → 总耗时 < 15 秒。

### 制造站产物分配

243 布局下 4 个制造站默认为 **2 经验 + 2 赤金**。经验优先于赤金穷举排序（经验几乎完全依赖基建产出，赤金超出贸易站消耗则价值归零）。

### 剩余设施贪心：支配偏序

制造站分配完成后，剩余设施（Trade / Control / Power / Reception / Office）从剩余池贪心取值。排序使用支配偏序：

```
A 支配 B  ⇔  e_A(t) ≥ e_B(t)  for all t ∈ [0, T]
```

对于绝大多数常数型技能，支配关系退化为 O(1) 二维比较：

```python
A dominates B iff k_A >= k_B AND t_red_A >= t_red_B
```

贪心按资源链优先级：Trade → Control(固定) → Power → Reception → Office。每个设施取排序后的前 N 名（前序设施已占用的干员跳过）。

### 体系联动

联动是 `synergy_efficiency(operators, room_type, product)` 构造器的一部分——以全房间干员列表为输入，输出聚合常数段参与 `P(t)` 积分。

| 联动类型 | 处理方式 |
|----------|----------|
| 同房联动 A1-A6 | Phase 2 制造站穷举中完整评估（16 个独立函数，见联动体系文档） |
| 跨设施联动 B1-B7 | Phase 1 预计算为常数 → Phase 5 精确验证时注入 |
| 中枢全局 C1-C2 | 固定方案（令+重岳+夕+凯尔希+焰尾），降至常数 |

详细联动建模见 [`synergy-systems.md`](./synergy-systems.md)。

## 效率计算

### 制造站

- 作战记录基础速率：1 个/3h → `0.333/h`
- 赤金基础速率：1 个/1.2h → `0.833/h`
- 12h 产出 = `base_rate × ∫₀¹² P(t) dt`

### 贸易站

- 订单平均耗时 3.39h，平均消耗 2.9 赤金/单，平均产出 1450 LMD/单
- 效率作用于订单耗时：`实际耗时 = 3.39 / P(t)`
- 12h 订单数 = `∫₀¹² P(t) dt / 3.39`

### 发电站

- 基础恢复 6 min/架 → 240 架/天 → 12h = 120 架
- 发电站干员不消耗心情 → `e(t)` 为纯常数，无 `t_red` 截断
- 无人机加速目标默认为 Trade[0]

### 赤金供需

```
赤金产出 = Σ 赤金制造站 12h 产出
赤金消耗 = Σ 贸易站 12h 消耗
有效 LMD = 总 LMD × min(赤金产出/赤金消耗, 1)
```

赤金不足时贸易站开工率按比例折算。
