# 基建排班策略概要

> **版本**: 2026-05-28 · MVP — 全box满练，单次12h排班，产能最大化

## 核心原则

**MVP 阶段唯一目标：全box满练（415干员，全精2），243布局，单次12小时排班下的产能最大化。**

不做多班次轮换，不做 box 大小适配，不做练度过滤。当前只回答：**在 29 个核心工位上，放哪 29 个人能让 12 小时产出最高？**

## 数据链路

| 文件 | 来源 | 内容 |
|------|------|------|
| `character_identity.json` | ArknightsGameData 清洗 | 415 干员 → buffId + phase |
| `buffs_infrastructure.json` | ArknightsGameData 清洗 | buffId → roomType + efficiency + description |
| `operators_data.json` | MAA OperBox 回调 | 玩家干员练度（MVP 全部视为精2满级） |

## 设施容量（243 布局）

| 设施 | 房间数 | 每间 | 总工位 |
|------|--------|------|--------|
| Control | ×1 | 5 | 5 |
| Trade | ×2 | 3 | 6 |
| Mfg | ×4 | 3 | 12 |
| Power | ×3 | 1 | 3 |
| Reception | ×1 | 2 | 2 |
| Office | ×1 | 1 | 1 |
| Dormitory | ×4 | 5 | 20 |

> 核心工位 29 个。全box 415 干员中精2可用 ≥225 名 → 干员/工位比 ≈ 7.8:1。

## 约束

**硬约束（不可违反）：**

| # | 约束 | 说明 |
|---|------|------|
| H1 | 人数上限 | Control≤5, Trade≤3/间, Mfg≤3/间, Power≤1/间, Reception≤2, Office≤1 |
| H2 | 一干员一工位 | 同一干员不能同时出现在两个房间 |
| H3 | 技能解锁 | MVP 全部精2 → 所有技能可用 |
| H4 | 设施类型匹配 | 干员技能 `roomType` 必须匹配目标设施 |
| H5 | 产物类型匹配 | 制造站产物必须匹配干员技能 |

**优化目标**：12 小时总产出最大化。产出 = `base_rate × Σᵢ ∫₀¹² Pᵢ(t) dt`，其中 `Pᵢ(t)` 是房间 i 的总生产力函数。

## 求解架构

```
全box干员池 (415人, 全精2)
       │
       ▼
Phase 1: 制造站穷举（CR 2间 + PG 2间）
   按产物分离 (CR ~60人 / PG ~56人)
   剪枝规则过滤 → ~1,500 种组合/产物
   每种组合: 计算个体效率 + A1-A6 同房联动
            + 计算最优支撑干员（中枢/贸易站/宿舍/办公室）
            → 产出积分排序
   跨间贪心分配（冲突时优先高分组合）
   锁定支撑干员（供后续 Phase 使用）
       │
       ▼
Phase 2: 中枢填充
   来自 Phase 1 累计的支撑需求（迷迭香→塑心/爱丽丝，骑士→薇薇安娜/焰尾 等）
   不足 5 人 → 从未分配的 Control 技能持有者中贪心补满
       │
       ▼
Phase 3a: 贸易站穷举
   C(n,3) 穷举（与制造站同架构）
   含订单机制（孑/但书/鸿雪/佩佩 等）的 LMD 产出评估
   中枢已确定 → 直接用实际中枢计算 global_bonus + buff_pool
       │
       ▼
Phase 3b: 剩余设施贪心
   Power(3人) → Reception(2人) → Office(1人)
   从剩余池按支配偏序贪心取值
   释放 Phase 1 锁定的 Office 干员参与分配
       │
       ▼
Phase 4: 宿舍填充
   优先 B 层生成者（塑心/车尔尼/爱丽丝 等）
   任意填充至 20 人
```

### 支撑干员锁机制

这是重构后最关键的架构变更——中枢不再固定预设，而是由制造站组合的支撑需求动态决定。

`compute_optimal_support()` 扫描制造站 combo 中的干员，识别需要的支撑：

| combo 特征 | 需要的支撑 |
|------------|-----------|
| 迷迭香在制造站 | 塑心/爱丽丝↔宿舍，车尔尼↔宿舍，黑键↔贸易站，絮雨↔办公室 |
| 骑士在制造站 | 薇薇安娜↔中枢，焰尾↔中枢 |

支撑干员在 Phase 1 被锁定（进入 `assigned_ids`），Phase 2 中枢填充时优先使用。

### 制造站穷举与剪枝

四条剪枝规则将 C(60,3)=34,220 种压缩至 ~1,500 种：

1. **纯效率等价类合并**：36 个纯效率干员无联动关系，保留一种代表即可
2. **联动锚点 × 配套池筛选**：有水月没标准化提供者是死组合，仅保留有效配套
3. **逐槽位上界预判**：upper_bound < best_known × 0.95 跳过（O(1) 判定）
4. **产物分离**：CR 和 PG 两条独立链

243 布局默认 **2 经验 + 2 赤金**。经验优先于赤金穷举排序（经验完全依赖基建产出，赤金超出贸易站消耗则价值归零）。

### 支配偏序排序

剩余设施贪心使用 e(t) 支配偏序而非标量排序：

```
A 支配 B  ⇔  e_A(t) ≥ e_B(t)  for all t ∈ [0, 12]
```

对常数型技能退化为 O(1) 二维比较（效率值 + 有效时长）。互不支配时退化为全积分比较。

## 效率计算

所有技能效率统一归约为时间函数 `e(t)`（LinearSegment 列表）。四种基本形态：

| 形态 | e(t) 表达式 | 示例 |
|------|------------|------|
| 常数 | `k` | `manu_prod_spd[000]` efficiency=15 |
| 线性爬升 | `min(k₀ + r·t, ceiling)` | 7 条时变技能（发电站/制造站/会客室爬升） |
| 心情门控 | `k₁` 或 `k₂`（mood 阈值切换） | mood<12→人间烟火+15 |
| 体系联动 | 跨干员聚合常数段 | "与推进之王同贸易站时+35%" |

12h 单班次下心情截断不触发（最差单人工位 `t_red = 16h > 12h`），e(t) 退化为全常数段。详细建模见 [`efficiency-function-design.md`](./efficiency-function-design.md)。

### 房间生产力

`P(t) = 1 + 0.01·n + Σ eᵢ(t)/100`，其中 n 为房间人数，eᵢ(t) 含干员独立技能 + 体系联动产出。12h 产出 = `base_rate × ∫₀¹² P(t) dt`。

### 各设施产出

| 设施 | 基础速率 | 产出公式 |
|------|----------|----------|
| 制造站（作战记录） | 0.333/h | `0.333 × ∫₀¹² P(t) dt` |
| 制造站（赤金） | 0.833/h | `0.833 × ∫₀¹² P(t) dt` |
| 贸易站 | 3.39h/单 | 订单数 = `∫₀¹² P(t) dt / 3.39` |
| 发电站 | 240 架/天 | 不消耗心情，e(t) 为纯常数 |

### 赤金供需

```
赤金产出 = Σ 赤金制造站 12h 产出
赤金消耗 = Σ 贸易站 12h 消耗
有效 LMD = 总 LMD × min(赤金产出/赤金消耗, 1)
```

## 联动体系

| 联动层 | 范围 | 处理方式 |
|--------|------|----------|
| A 层（A1-A7） | 同设施内 | Phase 1 制造站穷举 / Phase 3a 贸易站穷举中完整评估 |
| B 层（B1-B7） | 跨设施 | 通过 `evaluate_room()` 注入（buff_pool / 全局阵营 / 跨房配对） |
| C 层（C1-C2） | 中枢全局 | 中枢确定后计算 global_bonus，注入各房间评估 |

详细联动建模见 [`synergy-systems.md`](./synergy-systems.md)。
